# AI_LOG

## Инструмент

Использовал OpenAI Codex (GPT-6) для чтения требований PDF, разбора исходников и ошибок из Swagger/curl, а также для подготовки изменений и тестов. Решения сверял с заданием и фактическим поведением API.

## Ключевые запросы

1. «Почему `docker compose up --build` не собирает приложение и не применяет миграцию?» Контекст: лог сборки, Dockerfile, Compose и конфигурация Alembic. По результату выяснили, что Dockerfile копировал отсутствующие миграции.
2. «Доработай ошибки для неизвестного промокода и тарифа; проверь порядок проверки платежа и подписи вебхука». Контекст: требования PDF, код схем и обработчиков, реальные ответы Swagger. Добавили привязку ошибок к полям запроса и проверку существования платежа перед подписью, как требуется для `404`.
3. «Сверь тестовое задание с приложением и исправь недостающие пункты». Контекст: весь PDF и структура репозитория. В результате добавили начальную миграцию, CI workflow и тест `404` для вебхука без существующего платежа; документацию привели в соответствие с проектом.

## Что перепроверил

Сначала модель не учла, что запрос с `method: "card"` и `installment_months` отклоняется Pydantic до проверки тарифа или промокода. Это стало ясно по ответу Swagger; валидацию поправили, а для проверки тарифа поле нужно убрать. Ещё сначала не заметили, что Git игнорировал `migrations` и `.github`: новые файлы появились на диске, но отсутствовали в `git status`. Проверил это через `git check-ignore` и поправил `.gitignore`. При отладке подписи также выяснили, что HMAC зависит от точных байтов JSON: форматированный Swagger body не совпадает с компактным телом из Python-скрипта.

Понимаю, что график рассрочки — это расчёт частей в копейках, а не отдельные списания; HMAC подписывает точное тело запроса; неизвестный платёж в вебхуке должен дать `404` до проверки подписи. Для этого сценария добавлен тест.
